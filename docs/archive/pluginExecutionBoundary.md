## 必须保留的宿主接口

以 `packages/toolScaffold/src/runtime.ts` 和实际八类内置工具为依据：

- SDK 的 defineTool 与 read/write/edit/ls 构造器包含函数与闭包，不能直接结构化克隆到子进程。工具参数、描述和结果可传输，SDK 构造与执行必须明确归属。
- 文件接口返回 Buffer、Stats 和文件列表；Stats 的方法需要保留语义。路径授权、打开文件保护、原子写入、排他写入和进程内写锁继续由宿主掌握，不能在子进程另起一套写入锁。
- 画布、提问器、技能和媒体任务会回调宿主；技能 list、节点名称等还有同步接口。必须显式处理这些契约，不能把函数丢弃或静默返回 undefined。
- 媒体调用先经过能力、费用和用户确认，再进入稳定任务编号。插件超时、断开或退出后仍以宿主持久任务为准；提交是否发生无法确认时保留未知状态，不能自动重新生成。
- FFmpeg 工厂包含链式调用、事件和回调；现有 JSON 桥可复用于支持的调用，但不能据此宣称已保留原生工厂全部流接口。
- execute 的进度回调、AbortSignal 和 Agent 会话上下文需要单独转发。MCP 当前明确不提供完整 Agent 会话能力，应保留明确拒绝语义。

## 后续实现与验收门槛

目标是把工具的加载、配置校验、定义创建与执行移出桌面宿主，并继续处理供应商和界面代码的执行边界。子进程只接收当前插件、配置与本次工作区所需数据；文件、画布、提问和持久媒体任务通过明确宿主能力调用。打包时必须包含实际工作进程及其依赖，不能依赖开发机 node_modules。

初始化和配置解析需要有界，执行应可取消。长时间 FFmpeg、用户答复和供应商等待不能简单按短初始化超时截断。进程异常退出后报告原操作失败或待核对，终止待处理回调并清理本次资源；不自动重发执行，不清除原任务证据。其他项目及宿主应继续可用。

验收需覆盖：模块顶层死循环/退出、配置错误、定义创建异常、运行中取消与崩溃、合法文件和画布回调、技能与提问、媒体保存及未知提交、FFmpeg、跨项目并发和不同插件修订。另需实际安装包中的冷启动与重开证据。可信插件仍以当前用户权限执行；普通子进程本身不提供文件、网络或凭据的操作系统级权限隔离。
