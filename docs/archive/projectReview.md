# 零幕项目检查记录

检查日期：2026-10-05。范围为本次首页改造、项目文件流程与模型渠道修复。

## 本次完成

- 默认直接进入零幕首页：深色点阵背景、电影风轮播、创作输入框、提示词入口、项目列表；适配手机宽度。
- 生图、视频、音乐入口切换创作方向，使用已有画布和 AI 助手；尚未实现独立生成工作站。
- 首页提供项目搜索、导入、新建、重命名和列表切换；素材入口复用全局素材库。
- 零幕仓库、上游项目及教程链接集中到设置的“关于”；保留开源署名和许可。

## 已修复

1. 已有项目从首页继续创作被错误判为“非空文件夹”。现在仅给空目录新建画布，已登记项目可继续打开。
2. 未配置文本模型时直接发起创作。现在先引导配置，并保留输入草稿。
3. 渠道地址已经带 `/v1` 时重复拼接路径。统一 URL 拼接，兼容反向代理前缀。
4. 清空 API Key 后仍使用旧密钥。明确传入空值时不再回退；支持无需密钥的本地服务。
5. 批量拉取被忙碌锁拦截、成功提示与实际保存不符。批量内部保存可执行，只统计保存成功的新增模型，失败恢复模型列表。
6. 没有已保存模型时无法首次批量拉取。有效渠道即可拉取。
7. 刷新渠道覆盖其他行的未保存草稿。保留已修改行，更新服务端版本信息。
8. 默认模型保存失败缺少反馈。现在捕获错误并提示。
9. 网页类型检查被桌面 SDK 配置依赖阻断。应用版本抽到共享的 `appVersion.ts`。
10. 跳转到输入框的页内锚点干扰 hash 路由。改为按钮聚焦输入框。

## 验证结果与边界

- 网页、后端类型检查通过；全仓检查中 26 个包通过，桌面端未通过。
- 网页与后端生产构建通过。网页仍有较大打包分块提示，可后续优化。
- 使用隔离数据完成设置保存读取、模型列表拉取、项目打开检查、画布写入读取、重复创建冲突和路径越界拒绝的实际 HTTP 验证。
- 使用本地模拟服务和内联断言验证媒体 URL、图片 base64、音频二进制、视频提交/轮询路径与认证头处理。
- 浏览器验证首页、关于链接、素材入口、提示词填入、首次批量拉取并保存 2 个模型、项目导入与画布打开、返回首页、缺少文本模型时引导设置。
- 检查了 1440px 桌面、390px 手机以及应用内实际窗口宽度的首页。
- 独立收尾审查结论为 `ship`：三种宽度的首页主要入口和相关静态代码可交付。其截图未覆盖完整项目列表与设置弹窗，不代表这些部分经过独立视觉审查。
- 桌面端缺少 `.hutch/devkit` 和 `electrobun/main` 对应声明，尚未完成桌面打包验证；没有用虚假声明绕过。
- 未调用付费模型，因此第三方真实图片、视频、音频生成的端到端行为仍需配置可用渠道后验收。

本记录描述已执行的检查，不代表项目不存在其他缺陷。临时数据、日志和验证服务产物均位于被 Git 忽略的 `build/`，未改写用户真实设置。
