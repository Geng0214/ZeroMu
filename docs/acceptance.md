- 每项记录应用版本/构建摘要、源码范围、设备、数据基线、操作、实际结果、失败与例外、证据位置。

## 统计方式

| 指标 | 口径 |
| --- | --- |
| 首次独立完成 | 5–8 位真实目标用户逐人记录；建议至少 80% 可独立生成并保存，保留小样本限制 |
| 主动操作 | 有效凭据后至提交的操作时间；首轮目标中位数不超过 15 分钟，供应商等待另列 |
| 任务/恢复 | 核心场景记录覆盖目标 100%；恢复成功与明确待核对分开统计 |
| 候选与成本 | 采用数/全部候选数按模型、媒体与作品分组；实付、估算、未知、币种分开 |
| 性能 | 就绪时间、交互、逐条 >50 ms 长任务、宿主 RSS、渲染堆、媒体与 GPU 范围分别记录 |
| 导出与大包 | 输入/输出字节、创建/完成时刻、帧数、取消写入量、原件摘要与独立恢复 |

工具往返不称为 INP，累计布局时间不等同单条长任务，两次不同 GC 时刻的内存值不称稳定优化率。未采集指标留空，不补造通过结论。

## 性能通过标准

以下是 2026-10-23 新设定的验收目标，**整体尚未通过**。使用上述固定参考机、相同媒体摘要、窗口/字号和缓存条件；先对 2.0.24 参考资源采集参考值，再核对最终候选，保留两边的版本、每次值与中位数。当前已有一次两版冻结资源的隔离便携运行对照，见 性能对照记录（本机 `work/performanceComparison226/warmOpenComparison.json`，验证记录仅本机留存，未随仓库分发）；它不等同两版安装版的完整性能验收。历史工具往返观测不能直接代入基线。另一设备单列环境、结果及阈值，不借用参考机的通过结论。

| 项目 | 通过条件 |
| --- | --- |
| 暖开就绪 | 小项目中位数 ≤3 秒，300 节点大项目中位数 ≤10 秒；各至少 3 次，从开始加载到节点、连线及可见文字就绪，不包含主动播放原媒体 |
| 常用交互 | 选择节点、打开面板及文本输入合计至少 30 次有效事件到下一次呈现的记录，p95 ≤200 ms；没有有效呈现记录时保留未验收，不用自动化往返时间替代，也不将该样本称作整场 INP |
| 大包处理 | 约 1.20 GiB 固定样本的完整导出、独立恢复各至少 3 次，中位数分别 ≤30 秒；原件及恢复媒体摘要 100% 一致，取消不损坏原项目 |
| 回退控制 | 同工况候选的就绪时间、包处理时间、宿主 RSS 和渲染堆各不超过新采集参考中位数的 120%，同时满足上述绝对时间目标；内存须保持可比采样/GC 状态，缺少可比数据即未验收 |
| 冷开与异常 | 单独记录冷开、缓存准备和逐条 >50 ms 长任务；出现持续无响应、崩溃、数据损坏或原件改变即不通过，不能用平均值掩盖 |
