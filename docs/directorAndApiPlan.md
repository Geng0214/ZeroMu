## API 保护方案与边界

原有风险是配置文件明文保存 API Key，且完整 settings 返回前端。当前已通过系统凭据库、认证加密、脱敏响应和后端凭据解析修复；具体实现与实际验证见 [API 凭据安全报告](apiCredentialSecurity.md)。

导入的 Key 在输入时出现在密码表单，保存后由本机后端托管。随机主密钥通过 Bun.secrets 使用 Windows 凭据管理器保护，凭据字段以 AES-256-GCM 密文落盘；接口只返回配置状态。更换 Windows 账户或电脑导致解密失败时，保留原密文并允许重新输入；不能静默清空或退回明文。

[Microsoft DPAPI 文档](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)说明保护通常绑定相同登录凭据和计算机。它防止直接复制配置文件读取 Key，但不能防御已取得当前用户权限的恶意程序、可信插件或管理员。商业中转站的上游 Key 应只存放在服务端；客户端仅持有可撤销、可限额的用户凭据，不能将商户总 Key 打包进 App。
