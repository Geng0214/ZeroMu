## 应用与数据

| 层 | 职责与入口 |
| --- | --- |
| Web | Vue/Pinia/Vue Flow；首页、工作站、画布、素材与成片界面 |
| Server | `apps/server/src/app.ts` 的 `createApp` 装配路由，独立入口负责监听；桌面复用应用 |
| Desktop | Electrobun 宿主提供目录、保存、协议与更新；Windows 页面使用受限原生桥模式 |
| 扩展 | 节点、工具、供应商、团队、Skill 各有格式与生命周期，不混作同一种隔离范围 |
| 数据 | 本机设置/插件放应用数据目录；画布、素材和制作记录放所选项目；实际配置不能随程序资源替换 |

内部 `@toonflow/*` 包名与兼容格式保留；桌面使用 `local.zeromu.desktop` 和 `zeromu://`，不覆盖既有安装身份。

## 制作记录与文件

### 工作空间与项目目录（2026-10-24）

用户选择工作空间，再新建或打开项目。首页、画布列表、创作中心和设置可直接浏览；新建或导入画布、生成作品及进入画布编辑器时需要当前项目，不自动创建应用内部的默认项目。左侧 03 为“我的项目”，04 为“提示词库”，05 为“我的素材”；顶部项目名称也可进入项目管理。创作中心未选项目时可先填写内容，选择项目后保留草稿。

```text
工作空间/
├─ zeromuWorkspace.json          # 空间标识、上次项目的相对位置
├─ projects/
│  └─ 项目名称/
│     ├─ zeromuProject.json       # 制作关系与版本记录
│     ├─ canvases/               # 多张画布 JSON
│     ├─ media/{images,videos,audio}/
│     ├─ references/             # 节点上传、创作参考、固定版本
│     ├─ exports/                # 成片导出
│     └─ projectData/
│        ├─ layout.json
│        ├─ drafts/              # 图片、视频、音频分别保存
│        ├─ history/
│        ├─ tasks/               # 可随项目移动的历史快照
│        ├─ backups/
│        └─ cache/
├─ library/{files/,metadata.json}
└─ promptLibrary/{library.json,templates.json}
```

新项目使用上述布局；复制导入的旧项目保留原目录和相对引用，来源不改写、不覆盖。`projectData/layout.json` 区分新布局，业务路径通过统一映射保持旧项目兼容。生成服务按媒体类型分类保存，节点上传归入 `references/nodes`，创作中心与画布使用同一当前项目。

任务在开始时固定项目，切换项目或空间不改变其保存位置。应用数据目录保留调度恢复记录，项目内另存不含凭据的任务快照；移动或恢复项目时历史任务只读，不自动重新付费提交。项目包归集画布、三类媒体、参考、草稿、制作关系与任务历史，排除密钥及应用设置。

工作空间选择记录、API 密钥、模型设置及插件仍保存在应用数据目录，程序更新不移动真实作品。已有应用数据中的素材库与提示词原文件保留；新工作空间使用自己的共享库。

- 镜头、素材、固定版本、候选、采用、任务与导出建立稳定关系；画布是同一制作内容的视图，不另存一份互不相关的采用状态。
- 生成前固定项目、参数、参考顺序与版本。切换页面或修改设置不改写原任务输入；更新角色资料不自动修改旧候选或重生成。
- 完整快照使用原子写入；新建使用独占语义。统一文件原语在 `@toonflow/file`，前端通过 `useWorkspaceFiles` 访问项目。
- 文件原语不替代路径授权、工作区边界、冲突锁或业务事务。多步异步操作使用开始时固定的项目上下文。
- 草稿、参考与历史随项目持久化，损坏读取不静默覆盖。归档保留实际依赖和任务依据；凭据及本机配置不随包迁移。

## 任务与媒体

统一持久任务服务由工作站、节点和 Agent 使用。相同编号与输入读取原记录；冲突拒绝。状态区分校验、提交、查询、下载、部分完成、可恢复、失败与未知提交。

恢复只查询已确认的供应商任务或保存已有结果，不把无响应当作可以再次付费提交。停止调用方等待、取消排队、供应商终止和计费终止分别展示。费用保存估价依据、原始用量、账单状态与币种；缺失的实际账单保持未知。

FFmpeg/ffprobe 负责本地转换、预览与成片；Windows 配音使用本机音色；BiRefNet 在本机独立进程推理。已有结果不依赖原渠道仍启用才能查看。具体使用见 [创作说明](guides/creation.md)。

## 插件执行位置

| 路径 | 当前源码范围 | 尚不能据此证明的范围 |
| --- | --- | --- |
| 工具配置 | 独立进程加载/校验，有初始化时限、异常保护与清理 | 任意恶意插件的操作系统权限隔离 |
| 工具执行 | Agent/MCP/团队通过独立进程实例；能力引用按调用范围释放，取消后拒绝新增能力，已开始文件写入结束后清理 | 真实模型团队/A2A 所有多轮路径已验收 |
| 同步钩子 | prepareArguments、renderCall、renderResult 在插件进程；SDK 组件/状态/主题/焦点保留；同步等待总上限约两秒 | 完全无阻塞，或最新候选已安装并完成原生显示验收 |
| 媒体供应商 | 模块加载、元数据与生成在工作进程；宿主保留凭据使用、持久任务与保存 | 对当前用户全部文件/网络权限的沙箱 |
| 工具界面 | 独立页面及受限交互协议，支持提问、复制、定位与显示偏好；2.0.26 安装版两张子页面的 CSP、权限策略及六个相关全局对象的 `typeof` 已由 WebView2 直接核对，所查子页面均为 `undefined` | 所有间接通道或操作系统权限边界已全部审计，或节点界面已隔离 |
| 原生桥 | 主页面受限模式，工具子页面残留通道已修正；2.0.26 原生安装、重开及历史卡片有记录，2.0.27 安装、重开及界面修正另有记录 | 所有页面、节点、第三方插件均已隔离 |

工具传输约束宿主引用、反射入口与工作区能力；取消及释放清理等待和子进程。FFmpeg 保留原生流、进度、克隆和取消语义。新同步钩子已进入已安装的 2.0.26 和 2.0.27 候选，安装版真实 Agent 会话仍待验收。2.0.27 的模型弹层问题面板为 0；此结果不外推到节点脚本，其 UMD 仍注入主页面。

独立进程有助于异常、超时及生命周期隔离，**普通用户进程仍有当前用户权限**。安装扩展仍是信任决定，不把这些机制描述成运行任意不可信代码的安全保证。

### 节点界面隔离迁移清查（进行中）

`loadNodeComponent.ts` 当前把 `*.umd.js` 直接作为主页面脚本注入，`index.vue` 将 Vue、Vue Flow、Element Plus 与 Pi SDK 暴露在 `window.toonflowNodeHost`。八种内置节点和后来安装的同格式节点都使用这条路径。因此现有 2.0.27 原生桥与工具卡片结论不能证明节点代码隔离。

| 需要迁移的关系 | 当前入口 | 子页面契约及宿主责任 |
| --- | --- | --- |
| 节点与连线状态 | `useNode`、`useNodeReferences`、`nodeInputs`、`nodeSkeleton` | 宿主保留 Vue Flow 节点外壳、拖动、选中和端口；子页面接收限定节点的数据、有效上游输入及配置快照。数据修改带项目、画布、节点身份和修订号回传，宿主校验后提交。 |
| 生命周期与 Agent 函数 | `nodeEvent` 的 save/delete/copy/canConnect/canUnload、`nodeTools.register` | 宿主维护注册表，只向对应活跃子页面发送指定事件；函数声明由宿主登记，调用参数按声明核验，请求有时限与取消，页面销毁后注销。连线校验须有明确同步策略，否则默认拒绝新增连接。 |
| 工作区与草稿 | `workspaceFiles`、文本节点 `localStorage`、媒体预览 | 宿主固定目录和节点身份，仅代理允许的相对路径与文件操作；文本草稿通过宿主固定键读写，未落盘时保持不可卸载。二进制与预览按需传输并释放，不向子页面开放任意本机服务请求。 |
| 模型、任务与本地媒体 | `nodeAi`、`nodeFfmpeg`、生成节点与导演台 | 宿主负责能力预检、真实提交、任务归属与取消；每次操作绑定固定项目及节点，未知提交保持待核对。FFmpeg 和导演跨节点动作按具体命令代理，不能把通用 HTTP 或画布对象传入子页面。 |
| 外观与浏览器能力 | `nodeSkeleton`、Element Plus、视频播放器、3D 场景 | 子页面内自带运行时和样式，以快照同步主题、字号和可见状态；按需求传入媒体字节。摄像头、麦克风、定位、剪贴板和通用网络保持关闭；3D 指针锁、导出和可见性另作原生回归。 |

采用现有工具卡片的 `sandbox="allow-scripts"`、不带 `allow-same-origin` 的 `srcdoc` 与 MessageChannel 思路，但节点脚本、Vue 运行时和节点组件只在子页面加载。初始消息只含该节点所需快照；后续操作使用固定来源的端口、白名单动作、大小与频率上限、AbortSignal 和卸载清理。父页面必须核对项目/画布/节点仍相同，尤其是在异步文件写入、生成或画布切换后。不能把直接请求本机 `/api`、共享 `window` 对象或父页面 Vue Flow 实例重新开放给插件，否则仅改变脚本位置而没有隔离。先迁移显示与文本节点，再迁移三类生成节点，最后迁移导演台；每类完成后验证保存重开、取消、节点函数、连接和画布性能。

显式 `nodeFramePilot=1` 现将七种非导演内置节点 UMD 只送入独立来源的受限子页面，导演台和插件节点仍走 `loadNodeComponent.ts` 主页面注入。`nodeFrameProtocol.ts` 绑定项目、画布、节点及一次性会话，限制请求层级、字段、大小、速率、并发和动作；仅自身媒体文件写入可在单请求、单并发下达到 100 MB，文本草稿写入按 UTF-8 限 1 MB，其他动作保持 1 MB。`nodeFrameFiles.ts` 只允许节点自身目录写入和有限读取；并发初始化时合并共享目录创建，建目录和独占新建遇到 `EBUSY` 时短暂重试，不重试普通覆盖写入。媒体预览使用初始快照明确授予的相对路径或自身目录，经宿主 4 MiB Range 读取并核对总长、ETag，通过端口转移字节；子页面在 100 MiB 上限内合成 Blob URL，释放时撤销。该实现已用 34 MiB 本机 WAV 验证完整装载与实际播放，但仍需等完整文件读取完毕，不能称为按进度流式播放。宿主保留 Vue Flow 外壳、拖动与端口；子页面进入视口附近时才挂载，离开后只有允许卸载且没有生命周期调用的页面会延时释放。文本试运行已接通数据回传、文件保存、输入快照、连线删除、复制、部分生命周期和只读模型列表。图片、音频和视频节点分别以本机小样本验证了预览/播放与重开；三个生成别名仅完成构建，未做界面实测。独立来源中的生成调用明确拒绝，避免在尚无宿主授权协议时提交任务。生产构建与当前 2.0.28 安装资源均包含隔离页面入口，只在 `?nodeFramePilot=1` 显式开启时使用；默认仍走主页面节点路径。2026-10-24 R0 从各自 HTML 入口递归核对资源引用：安装版引用 `isolatedNodeView-COA4cjKU.js`，既有 `build/web` 和本轮独立验证构建各自引用其他 chunk，不能只按版本号或目录内残留文件认定同一构建。浏览器文件选择器上传、超过 100 MiB 的媒体预览、真实生成、节点工具、导演台与插件节点、修订冲突协调、规模性能和原生权限验证仍未完成；不能计为完整节点隔离验收通过。

2026-10-24 R0 在现有子页面入口补齐 `retainNodeFiles`，防止删除节点时移除撤销所需的媒体原件；保存、复制和删除生命周期完成前等待节点数据写回宿主，待同步或失败时不允许视口回收。该修复完成类型检查、模块/受控消息核对及独立前端生产构建，尚未更新安装程序，也没有新增默认隔离迁移。证据见 R0 摘要（本机 `work/r0Audit/summary.json`，验证记录仅本机留存，未随仓库分发）。

## 凭据与本机服务

- 本机服务绑定回环地址，校验套接字、Host、来源与相关请求标记；工作区文件授权、预览令牌、内容安全策略及请求体限制各自保留。
- 凭据字段使用 AES-256-GCM 加密；随机主密钥经 Bun.secrets 存入系统凭据库。默认设置响应返回配置状态，避免返回已保存 Key。
- 地址与凭据使用目标绑定；导出不携带密钥。解密失败保留原密文并允许重新输入，不能静默清空或退回明文。
- 边界要说清：上述校验抵御的是**浏览器里的跨站请求**（Origin、Referer、`Sec-Fetch-Site` 由浏览器控制，页面无法伪造），不是同机进程的访问控制。`x-toonflow-workspace` 之类只是普通请求头，本机任意进程都能带上；桌面与开发模式下 `resolveWorkspace` 还允许工作空间之外的绝对路径。因此同一 Windows 账户下的其他进程等价于拥有本应用的读写与删除能力，这台机器上的隔离依赖账户与文件 ACL，不依赖这些请求头。拒绝文案「仅允许本机零幕页面访问」描述的是来源校验，不构成同机隔离承诺。
- MCP 按显式设置启用并验证凭据；临时验收结束后关闭、移除临时凭据并确认拒绝访问。桌面文件 API 不直接公网暴露。
- MCP 访问凭证 `settings.mcp.token` 与模型 Key 一样走凭据加密（AES-256-GCM + 系统凭据库主密钥，按 `/settings/mcp/token` 路径绑定），`settings.json` 内不再出现明文；设置接口仍向本机页面返回可读值，用于展示与复制。供 stdio 桥发现服务用的 `data/mcpRuntime<port>.json` 仍写入令牌明文（请求 0600 权限，Windows 上由 NTFS ACL 决定实际效果），这是当前已知取舍，读取该文件等价于持有 MCP 凭据。
- 更换电脑/Windows 账户需重新配置凭据。不能抵御已取得当前用户权限的恶意程序或管理员；普通正文中的私人信息仍需用户审阅。

依据：[凭据保护](archive/apiCredentialSecurity.md)、[桌面检查](archive/desktopSecurityReview.md)。这些是记录范围内的实施与验证，不是全面安全认证。
